# Maya 2026 workflow inventory seed

Research date: 2026-10-14. Status: provisional research, not an accepted denominator or implementation report. **Overall coverage is unmeasured.**

The user requires verified 80–90% of all Maya 2026 functionality before the first push. This initial 100-workflow seed spans major documented domains but is not complete. It cannot establish that requirement. Reconcile the installed interface, commands, node types, API references, bundled extensions and service boundaries before freezing an auditable denominator. The final objective remains identical interface and behavior; publication eligibility does not establish exact parity.

## Reference prerequisite and boundaries

Pin a runnable full Maya reference, not Maya Creative: exact 2026.x build, platform/CPU architecture, GPU/driver, locale, display scale, workspace/preferences, OCIO configuration, units and frame rate. Record every plug-in's version, API version, loaded state and entitlement. Capture fixtures and results from that installation. Documentation establishes candidate scope, not pixel, numerical or binary compatibility.

### Documented baseline components, installation/version verification pending

- Maya's five menu sets cover Modeling, Rigging, Animation, FX and Rendering. See [Main menus](https://help.autodesk.com/cloudhelp/2026/ENU/Maya-Basics/files/GUID-3DB1C040-051F-4C2A-83F8-D806455FCEFF.htm).
- Bifrost is included with Maya but released separately. Its installer includes Graph, legacy Bifrost Fluids, BOSS and `bifcmd`. Pin the actual version rather than assuming that “Maya 2026” identifies one version. See [Bifrost installation](https://help.autodesk.com/cloudhelp/ENU/Bifrost-MayaPlugin/files/Bifrost_MayaPlugin_install_bifrost_for_maya_html.html).
- MayaUSD is included with Maya and supports independently installed versions. See [USD installation](https://help.autodesk.com/cloudhelp/2026/ENU/Maya-USD/files/GUID-8FB49D7F-8651-47CE-80FC-5C940E568C97.html).
- MASH and both XGen description families are documented Maya workflows. Loaded state and actual plug-in versions require reference inspection.
- Arnold/MtoA, LookdevX, Substance and update-specific features require exact component versions. MotionMaker is introduced in the 2026.1 update. See [2026.1 changes](https://help.autodesk.com/cloudhelp/2026/ENU/Maya-WhatsNew/files/GUID-5D9FAEE0-CB9A-41AA-9A7D-014F266C6578.htm) and [2026.2 changes](https://help.autodesk.com/cloudhelp/2026/ENU/Maya-WhatsNew/files/GUID-0C8224D8-23ED-417D-9630-1F925DC1767C.htm).

### Unresolved services, collection and third-party scope

- Flow Retopology is documented as included with Maya 2026, but its cloud execution and Flow Wedging require service/entitlement verification. Inclusion of a client control does not prove service availability or local compatibility. No paid jobs are authorized by this document.
- Golaem is documented as part of the Media & Entertainment Collection. It is not silently treated as a base Maya component or silently excluded from the user's intended scope. Resolve its inclusion explicitly.
- Enumerate the existing third-party plug-ins/scripts for compatibility testing. PyMEL is third-party and unsupported by Autodesk according to [Maya Python libraries](https://help.autodesk.com/cloudhelp/2026/ENU/Maya-Scripting/files/GUID-49701DA7-9224-424D-93F7-EC1DA779C99C.htm).
- Check native plug-in architecture/API requirements in the reference. [Plug-in loading](https://help.autodesk.com/cloudhelp/2026/ENU/Maya-Customizing/files/GUID-07A89E6C-199C-4719-98A0-11C3A2BCDF21.htm) documents version constraints and unknown-node behavior.

## Measurement proposal, pending acceptance

Freeze audited capability families and weights before implementation-based scoring. Give each family a fixed domain budget, then divide that budget among its capabilities/subcases. Splitting trivial tasks into more rows cannot increase the budget. Agree weights from production significance and breadth, not implementation effort. Report unweighted counts, each domain's coverage and weighted coverage together. Do not score this seed as the denominator.

A capability earns credit only after all mandatory reference comparisons pass: interaction, semantic output, persistence, undo where applicable, invalid inputs and interoperability. Unknown, untested, placeholder and partial results earn zero. Agree numerical/image thresholds in advance; distinguish reference repeatability noise from mismatches. Maintain links to exact application/reference versions, fixture hashes and evidence.

The first-push decision needs an agreed threshold within the user's range, an audited denominator, independent evidence, agreed minimum coverage in every major domain and critical must-pass workflows for scene preservation, actual simulation/rendering, scripting and existing plug-in execution. These proposed floors/weights are not approved yet. No major domain may disappear through averaging.

Existing plug-in compatibility requires executing existing plug-ins against their real API/ABI expectations. Newly written AztecCraft-only plug-ins do not prove Maya compatibility. Document unsupported architectures/APIs/entitlements explicitly and retain unresolved scope items until decided. No publishing, pushing or external service execution is authorized by this inventory. Until the reference and denominator are established, overall coverage remains unmeasured.
